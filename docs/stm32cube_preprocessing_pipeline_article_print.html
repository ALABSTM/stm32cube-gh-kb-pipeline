Engineering-Grade STM32Cube Preprocessing Pipeline

A publication-ready overview of the V2 pipeline for technical RAG readiness.

1. Executive Summary

The STM32Cube V2 preprocessing pipeline transforms raw GitHub issues and repository files into structured technical knowledge. Its key value is not only text normalization, but STM32-aware metadata extraction: layer, severity, issue kind, component, board, and quality validity flags.

2. Why This Pipeline Is Critical

Raw ingestion alone is insufficient for embedded support retrieval. Without domain metadata, a RAG system struggles to distinguish firmware-layer bugs from tooling questions, and board-specific incidents from generic discussions.

4. STM32 Metadata That Enables Precision

  • Issue metadata: layer, severity, issue_kind, component, board, is_valid.
  • File metadata: file_type, path, example_name, component, board, is_valid.
  • Similarity metadata: related_issue_ids for cross-ticket retrieval expansion.

5. Quality Evidence Snapshot (STM32CubeH7 Issues V2)

  • Layer distribution: HAL 47.6%, Middleware 21.4%, Other 18.7%, CubeMX 8.2%, LL 4.1%.
  • Severity distribution: medium 58.8%, high 31.6%, low 9.5%.
  • Issue-kind distribution: bug_report 54.4%, usage_question 23.1%, other 16.0%, configuration_help 6.5%.
  • Top components: USB, ETH, FREERTOS, UART, ADC, DMA, CAN.

6. Risks and Biases to Control

  • Heuristic over-attribution in mixed-context issues.
  • Board normalization that can become too generic.
  • Chunk-level context loss when comments are isolated from core bug narrative.

7. Priority Roadmap

  1. Build a labeled metadata audit set to measure per-field precision.
  2. Refine board and component detection order and lexical coverage.
  3. Harden chunk retrieval by recovering chunk 0 or merging weak comment-only chunks.

8. Deployment Guidance

For RAG ingestion, prioritize docs_issues_*_v2.json and docs_files_*_v2.json with is_valid=true. Add docs_issues_*_v2_sim.json when issue-neighbor recall is required. Use chunks_*_v2.json when target platforms do not provide internal chunking.

9. Conclusion

The pipeline is already strong enough for technical RAG pilots: reproducible, explainable, and domain-grounded. With focused metadata auditing and context-aware chunk hardening, it can evolve into a production-grade STM32 knowledge backbone.
