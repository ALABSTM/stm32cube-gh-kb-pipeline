Workflow STM32Cube Preprocessing Agent

Objectif

Transformer des donnees GitHub STM32Cube (issues + fichiers) en corpus fiable et exploitable pour un systeme RAG, avec un role central de l agent dans l orchestration, la qualite et la documentation.

Pipeline

  1. Ingestion issues: fetch_issues.py -> raw_issues_<repo>.json
  2. Ingestion fichiers: fetch_files.py -> raw_files_<repo>.json
  3. Cleaning issues: clean_issues.py -> clean_issues_<repo>.json
  4. Cleaning fichiers: clean_files.py -> clean_files_<repo>.json
  5. Docs issues V2: issues_to_docs_v2.py -> docs_issues_<repo>_v2.json
  6. Docs fichiers V2: files_to_docs_v2.py -> docs_files_<repo>_v2.json
  7. Similarite issues: compute_issue_similarity_v2.py -> docs_issues_<repo>_v2_sim.json
  8. Chunking optionnel: docs_to_chunks_issues_v2.py et docs_to_chunks_files_v2.py

Regle importante pour ST RAG

Si ST fait deja le chunking, injecter uniquement les fichiers docs V2 (issues et fichiers), et ne pas injecter les chunks pour eviter le double chunking.
